Open/Closed Principle — if/else vs Strategy

LLD · 01 — "open for extension, closed for modification." Add a payment type and watch who has to change.

class PaymentProcessor
Takeaway: with the if/else design every new payment type forces you to reopen and modify already-tested code — risky, and the class grows without bound. With the Strategy design you add a new class and the processor never changes — it was closed for modification yet open for extension. The seam is the PaymentMethod interface.
