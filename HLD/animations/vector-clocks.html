Vector Clocks & Causality

Three processes (P1, P2, P3) run top-to-bottom. Each local event, send, and receive updates a per-process vector clock. Click any two events and the tool tells you whether one happened-before the other, or whether they are truly concurrent — the distinction a single scalar Lamport timestamp cannot capture.

Press Play or Step to begin. Events appear in causal order.
Click two events to compare them.

Try this

Run the whole scenario, then click a1 (P1's first event) and c1 (P3's first event). Neither vector dominates the other, so they are concurrent — no message chain links them. Now compare a1 with the event on P2 that received P1's message: it strictly dominates, so it provably happened-after.
